# Тестирование

Цель тестирования - проверка соответствия ПО предъявляемым требованиям

Unit тестирование (модульное) - отдельные маленькие части системы:
 * функции
 * хелперы
 * методы класса
 * какой-нибудь небольшой компонент UI

Скриншотные тесты - например, сверстали страницу, сделали скриншот и забыли на долгое время.
Через время другой разработчик меняет шрифты и это ломает отображение страницы. Во время прогона тестов будет сделан второй скриншот.
Система наложит их друг на друга и сообщит о разнице.

Интеграционные тесты - когда тестируются несколько модулей в связке. Например, несколько React компонентов в связке.
Несколько классов, которые перескаются.

E2E тесты - полноценная связка frontend и backend. Когда пишем тесты, которые кликают на кнопку, ожидают какое-то конкретное
поведение, приходят ответы от сервера и т.д. Проверяем ключевой функционал (авторизация, удаление сущности, добавление сущности и т.д)


## Пропорции тестов

* e2e - 10% (сложное написание и поддержка, исключительно на ключевой функционал)
* интеграционные - ~20-30%
* скриншотные (по сути unit тест для ui) + unit - ~70-80%
